Personal project

Source on GitHub ↗

Systematic trading bot

A long-only swing strategy, ported from AmiBroker's AFL to Python on the Interactive Brokers API with AI-assisted tools. The strategy itself comes from published work by Critical Trading. My part is making it run unattended and safely.

The design problem

The machine shouldn't have to be awake at the market open. So the bot runs once before the session and hands the broker everything it needs: market-on-open entries, ATR-based stops and limit-on-close exits, linked so that one exit cancels the other.

Built to fail closed

A guard refuses to trade unless the session is provably a paper account, and it has no off switch. Order and position state lives in SQLite, a test suite pins down the strategy's behaviour, and the bot runs as a Linux daemon woken daily by rtcwake.

  • Python
  • asyncio
  • ib_async
  • SQLite
  • Backtesting
  • Linux

Paper trading only. I make no claims about returns, and this isn't financial advice.

Mathematics thesis · In progress

Symplectic integrators

Most numerical methods slowly drift away from the physics they simulate. Symplectic integrators preserve the geometric structure of Hamiltonian systems, which is why they behave so well over long simulations.

Supervised by Oscar Cosserat, I'm working from symplectic geometry and Darboux's theorem through Hamiltonian vector fields to Lyapunov stability, and then connecting that theory to computation.

  • Symplectic geometry
  • Hamiltonian mechanics
  • Numerical analysis

High-performance computing

Measuring parallelism

With a teammate, I ran MPI jobs on a shared 27-node OpenHPC cluster under SLURM and used Spark on Kubernetes. We measured latency, bandwidth and speedup, pinning nodes and taking medians so that other users' jobs wouldn't distort the numbers, and separated compute time from communication cost.

  • MPI
